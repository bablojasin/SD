# SPECTRE DEFEND • GitHub OAuth Authentication Specification

This document details the configuration of the GitHub OAuth Application and Cloudflare Worker token proxy for **SPECTRE DEFEND** and **Decap CMS**.

---

## 1. Quick Configuration Reference

When registering your OAuth application on GitHub, you must use your own credentials and the exact production domain:

| Field Name | Required Configuration Value |
|---|---|
| **Application Name** | `SPECTRE DEFEND Content Manager` |
| **Homepage URL** | `https://SpectreDefend.dpdns.org` |
| **Application Description** | `Decap CMS OAuth authentication proxy for SPECTRE DEFEND` |
| **Authorization Callback URL** | `REQUIRES WORKER URL` (e.g. `https://<WORKER_DOMAIN>/callback`) |
| **Client ID** | `REQUIRES GITHUB OAUTH APP` (Generated by GitHub) |
| **Client Secret** | `CLOUDFLARE WORKER SECRET ONLY` (Stored in Worker secrets; NEVER frontend) |

---

## 2. Step-by-Step GitHub OAuth App Setup

1. Log in to your GitHub account or organization.
2. Go to **Settings** > **Developer settings** > **OAuth Apps** (or visit `https://github.com/settings/developers`).
3. Click **New OAuth App**.
4. Enter the application details:
   - **Application name**: `SPECTRE DEFEND Content Manager`
   - **Homepage URL**: `https://SpectreDefend.dpdns.org`
   - **Authorization callback URL**:
     Enter your deployed Cloudflare Worker's `/callback` URL:
     `https://<YOUR-WORKER-DOMAIN>/callback`
     *(Example: `https://spectre-defend-oauth-worker.<subdomain>.workers.dev/callback`)*
5. Click **Register application**.
6. Copy the **Client ID**.
7. Click **Generate a new client secret** and copy the secret immediately.

## 3. Configuring Cloudflare Worker Secrets

The user must store their GitHub credentials securely into the Cloudflare Worker environment. Secrets are encrypted at rest by Cloudflare.

Navigate to the `worker/` directory and run the Wrangler CLI commands:

```bash
cd worker

# 1. Store GitHub Client ID
npx wrangler secret put GITHUB_CLIENT_ID
# When prompted, enter your value:
# Value: <YOUR GITHUB OAUTH CLIENT ID>

# 2. Store GitHub Client Secret
npx wrangler secret put GITHUB_CLIENT_SECRET
# When prompted, enter your value:
# Value: <YOUR GITHUB OAUTH CLIENT SECRET>
```

---

## 4. Why Client Secrets Must NEVER Be Exposed

1. **Why the Client Secret Must Never Be Committed to Git**:
   Git history is immutable and publicly visible in open repositories. Even in private repositories, hardcoded secrets leak through developer forks, CI logs, and third-party tools.
2. **Why the Client Secret Must Never Appear in `public/admin/config.yml`**:
   Files in `public/` are served as unauthenticated public static assets by GitHub Pages. Anyone can inspect `https://SpectreDefend.dpdns.org/admin/config.yml` in their browser and steal any secrets placed there.
3. **Why the Client Secret Must Never Be Exposed to the Browser**:
   If an attacker acquires the client secret and client ID, they can impersonate the application, forge OAuth token exchanges, and gain full write and delete permissions to the GitHub repository.
4. **How the Cloudflare Worker Secures Token Exchange**:
   - The user opens Decap CMS at `https://SpectreDefend.dpdns.org/admin/` and clicks "Login with GitHub".
   - The browser opens a popup to `https://<WORKER_DOMAIN>/auth`.
   - The Worker generates a cryptographic random state for CSRF protection and redirects the popup to GitHub's authorization page.
   - The author grants repository permissions. GitHub redirects the popup back to the Worker's `https://<WORKER_DOMAIN>/callback?code=...&state=...`.
   - The Cloudflare Worker performs a **server-to-server POST request** over HTTPS to `https://github.com/login/oauth/access_token` containing `GITHUB_CLIENT_ID` and `GITHUB_CLIENT_SECRET`.
   - The client secret **never** leaves the Cloudflare edge server and is **never** sent to the client browser.
   - The Worker receives the access token and safely delivers it to Decap CMS via a scoped `window.postMessage()` restricted strictly to target origin `https://SpectreDefend.dpdns.org`.

## 5. Decap CMS Configuration Link

In `public/admin/config.yml`:

```yaml
backend:
  name: github
  repo: GITHUB_REPOSITORY_OWNER/GITHUB_REPOSITORY_NAME
  branch: main
  base_url: https://WORKER_DOMAIN
  auth_endpoint: auth

site_url: "https://SpectreDefend.dpdns.org"
display_url: "https://SpectreDefend.dpdns.org"
```

Replace `WORKER_DOMAIN` with the actual hostname of your deployed Cloudflare Worker (without the `https://` prefix or trailing slash, as `base_url` handles the protocol).
